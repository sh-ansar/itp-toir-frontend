# Frontend-архитектура и UI-договор

Актуально для feature/toir-foundation, 04.11.2026.

## Основной поток данных

~~~text
Vue Router → проверка Session Store (Pinia)
          → Module View / Registry / Detail
          → типизированные src/api/{module}.ts
          → src/api/client.ts (credentials: include + CSRF)
          → Laravel /api/v1/*
          → company_id из backend-сессии, роли и доменная логика на сервере
~~~

Нельзя использовать company_id, пришедший от клиента, для обхода backend-tenant scope. Vue не управляет правами доступа к данным; она только отражает состояние и доступные действия.

## Назначение каталогов

| Каталог | Правило |
|---|---|
| src/router/index.ts | маршруты, auth guard, без бизнес-запросов |
| src/stores/session.ts | источник истины текущей сессии и компании |
| src/stores/preferences.ts | визуальные настройки пользователя |
| src/api/client.ts | единые ошибки, credentials, XSRF token, JSON |
| src/api/resources.ts | универсальные CRUD-адаптеры |
| src/api/operations.ts, stock.ts, checklist.ts, chat.ts | доменные API-операции |
| src/config/toirModules.ts | схема колонок/полей основных реестров |
| src/components/ui/* | повторно используемые элементы |
| src/components/toir/* | компоненты только для предметных процессов ТОиР |
| src/views/modules/* | композиция страниц, не хранилище доменной логики |
| src/styles/tokens.css | все семантические цвета, размеры и типографика |
| src/i18n/index.ts | строки интерфейса и переводы |

### Реестры и карточки

RegistryView и DetailView используют схему toirModules для стандартных ресурсов. При добавлении нового реестра сначала проверьте, подходит ли общий механизм. Для сложных процессов (наряды, чек-лист, риск-скоринг, склад) отдельные виджеты и API более безопасны, чем добавление ветвей в универсальную карточку.

### Авторизация

1. initializeCsrf() вызывает GET /sanctum/csrf-cookie.
2. POST /api/v1/auth/login создаёт сессионную cookie.
3. GET /api/v1/auth/me отдаёт роль, компании, профиль.
4. После /auth/companies/switch обновляется Session Store; нужно сбросить company-specific запросы, чаты и текущие фильтры.
5. После logout или 401 скрываются приватные страницы и данные.

Не создавать собственный auth token localStorage или хранение паролей в приложении.

### Дизайн-система

Используйте существующие BaseButton, BaseCard, BaseNotice, BaseFormField, BasePageHeading, BaseSearchField и компоненты toir. Цвета и размеры берите из tokens.css. Типографика: Golos Text с надёжными fallback; грузинский шрифт имеет отдельный fallback.

Компоненты унаследовали стиль HRM, **но физически находятся в этом репозитории**. При изменении HRM они не обновляются автоматически. Перед добавлением нового select/table/modal проверьте текущие компоненты и поведение на клавиатуре и мобильных экранах.

Обязательные состояния: loading, empty, form validation, forbidden, API failure, success. Проверка размеров: 320/390/768/1440 px. Недопустимы обрезанные диалоги, некликабельные кнопки и перетекание таблиц за основную страницу. Горизонтальный скролл самого реестра на узком экране допустим, если не ломает внешний layout.

### Локализация

Функциональность RU/EN/GE не полная во всех новых блоках. Новые UI строки оформляйте через словари i18n; не оставляйте кириллицу в новых шаблонах без соответствующего перевода, если пользователь может переключать язык.

## Известные технические долги

- DetailView ~580 строк, ChatView ~463 строки, WorkforcePlanningView ~333 строки — желательно декомпозировать на composables и вкладки.
- src/styles/toir-modules.css ~841 строка; разбить по модулям, сохранив единые токены и каскад.
- 87 обращений preview.enabled от старого демонстрационного слоя; store всегда возвращает false, источника фейковых данных уже нет.
- 22 нативных select вместо общей унифицированной библиотеки.
- На дату аудита нет ESLint/Prettier gate; действует vue-tsc + Vite build.
- Частично типы ToirRecord слишком широкие; для новых сложных API лучше отдельные DTO и explicit response schema.
- CSS-связь шрифта с общим URL нужно учесть при изолированном размещении, не копировать шрифтовые файлы в репозиторий.

## Тесты и приёмка

~~~powershell
npm ci
npm run typecheck
$env:VITE_BASE_PATH='/mro/'
npm run build
~~~

Не использовать production-аккаунты в автоматических тестах. Изолированный QA-контур 04.11.2026 прошёл 53 браузерные проверки 23 маршрутов и 18 адаптивных проверок, но эти сценарии временно лежат в qa-tools авторизованного Windows сервера и должны быть превращены в повторяемые Playwright tests внутри репозитория.

Страница не считается завершённой, пока не проверены реальные API-запросы, права всех ролей, ошибка сервера, мобильное состояние, локализация и отсутствие JS исключений.
