# ITP ТОиР — внедрение общей библиотеки, этап P1

Дата: 6 ноября 2026. Продолжение коммита `437c98b`.

## Принцип

Используется опубликованный архив `@itpmining/vue-basic-components` версии `0.10.0-reserve.4`, зафиксированный в `package.json`. Исходники библиотеки и её API не меняются. Прикладные компоненты оставлены только как адаптеры бизнес-логики и модели данных, а не как альтернативные дизайны.

## Что интегрировано

| Зона | Компоненты общей библиотеки | Поведение, остающееся за ТОиР |
| --- | --- | --- |
| Профиль и шапка | AccountMenu, CompanySwitcher, AppSwitcher, Switch | Смена компании через защищённый API, серверная проверка доступа к админке, выход, локальные настройки статуса |
| Чат | ChatLayout, ChatHeader, ChatFilterTabs, ChatConversationItem, ChatMessageBubble, ChatComposer, ActionMenu, Drawer, ConfirmDialog | Reverb, списки и права чатов, черновики, ответы, 15-минутное редактирование своих сообщений, отметки о доставке/прочтении |
| Рабочий календарь | PeriodCalendar, Button | Переключение недели и загрузка нарядов/смен по API; вид месяца/квартала/года служит **только навигацией**, не заменяет недельный график |
| Планирование и карточки | Button, UiCheckbox | Gantt-ячейки, режимы отображения, действия с нарядами |
| Типографика | Совместные WOFF2 Golos Text из UI-пакета | Приложение больше не запрашивает несуществующий `/hrm/fonts/GolosText.ttf` |

## Специальные контролы, которые не нужно механически заменять

- Интерактивные ячейки диаграммы Ганта, события на недельном графике и разворачивание дерева оборудования — это **бизнес-контролы**, а не универсальные кнопки.
- Демо-сцены публичного сайта включают специфические интерактивные схемы; их замена общей Button без проверки поведения нарушит демонстрацию.
- В форме чата кнопки голосового сообщения и вложения пока **не создают записи на сервере**: пользователь видит сообщение о недоступности. Для этого необходим отдельный backend-контракт; не имитировать отправку.

## Запуск и проверка

```powershell
npm ci
npm run typecheck
npm run build
npm run check:ui
npm run check:hero
git diff --check
```

Проверка через браузер на резервной машине — Playwright (1366 и 375 пикселей), маршруты с тестовыми ответами API: профиль, переключение компании, чат, отправка/удаление сообщения, отмена выхода из канала, меню, создание чата, режимы календаря и переход к выбранной неделе. Это **frontend-приёмка с mock API**, а не доказательство успешной работы SMTP, Reverb, БД или прав на реальном production.

## Перед переносом в main

1. Запустить проверки с настоящим тестовым backend и несколькими пользователями/компаниями; подтвердить изоляцию tenant и матрицу доступа.
2. Протестировать реальный Reverb: отправку, прочтение, тайпинг, переподключение и изменение состава канала.
3. Проверить в браузере светлую/тёмную тему, RU/EN/GE, уменьшенную ширину и мобильное меню. Сравнить скриншоты с Portal/HRM.
4. В проекте есть предупреждения о deprecated Sass `@import` и большом JS-чанке. Исправлять их отдельно, не меняя произвольно семантику компонентов библиотеки.

`main`, production и исходная библиотека не затрагиваются до приёмки.
