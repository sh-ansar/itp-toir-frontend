# ITP ТОИР · Frontend

Самостоятельная SPA (Vue 3, TypeScript, Vite, Pinia, Vue Router). До интеграции с Portal используется **собственная авторизация ТОИР** на HttpOnly-cookie без токенов в localStorage. Нет фейкового входа и демонстрационных паролей.

## Быстрый старт

\`npm ci\` (если package-lock уже создан), иначе \`npm install\`.

\`npm run typecheck\`
\`npm run build\`
\`npm run dev\`

Скопируйте \`.env.example\` в \`.env\`. По умолчанию dev-сервер Vite доступен на \`127.0.0.1:5173\`, а /api и /sanctum проксируются на \`127.0.0.1:8000\` (Laravel).

Production: размещайте frontend и backend на одном origin; SPA должен иметь history fallback на index.html, а /api и /sanctum должны идти на backend. Не раскрывайте APP_KEY и не копируйте cookies других продуктов. При размещении в подпапке установите VITE_BASE_PATH и настройте маршруты/статику вместе с reverse proxy.

## Переиспользованные компоненты HRM

Из \`sh-ansar/itp-hrm-frontend\` перенесены без визуальной переработки:
\`BaseButton\`, \`BaseCard\`, \`BaseFormField\`, \`BaseNotice\`, \`BasePageHeading\`, \`tokens.css\`, \`global.css\` и логотип ITP. Эти компоненты имеют семантические CSS-токены с поддержкой тёмной темы. Новые элементы обязаны использовать тот же набор переменных.

## Готовые маршруты

- /login — вход
- /forgot-password — запрос сброса (SMTP на backend)
- /reset-password — установка нового пароля по ссылке
- / — защищённый каркас ТОИР
- /profile — профиль, просмотр компаний, смена пароля
- 404 — неизвестные страницы

Оборудование/наряды/планы в меню пока недоступны: это сознательно, чтобы интерфейс не изображал рабочую бизнес-логику до её реализации. Все проверки прав на будущие CRUD выполняются на backend, не только в меню.


## Разделы первой версии

Согласно макету доступны: рабочий стол, наряд-задания, планирование (график и список), недельное расписание, сотрудники, проекты, активы (помещения, оборудование, инструменты и материалы), поставки, тендеры, отчёты по работам и складу, уведомления, чат, конфигурация и карточки записей.

Реальные CRUD-сценарии через API работают в реестрах активов, нарядов, сотрудников, проектов, планов, поставок и тендеров. Поиск и фильтры работают на сервере с company scope; сортировка — по загруженной странице; CSV экспортирует текущую страницу. Расписание и отчёты используют существующие данные, а не демонстрационные числа. Чат, загрузка документов, полноценные PDF/Excel отчёты и сложное планирование работ ещё не реализованы; интерфейс не показывает вымышленные сведения.

Из HRM переиспользованы базовые компоненты, токены светлой/тёмной тем и принципы построения таблиц и форм. Стилистика опирается на предоставленный ZIP макетов ТОИР и demo_bnt_dt.

## Независимое тестовое размещение

При проверке на сервере используется URL \`https://platform.itpmining.kz/mro/\` (временный URL, без авторизации Portal). Сборка под подпапку:

\`\`\`powershell
$env:VITE_BASE_PATH = '/mro/'
$env:VITE_API_BASE_URL = '/mro'
npm ci
npm run build
\`\`\`

В \`vite.config.ts\` намеренно задан \`build.assetsDir='toir-static'\`: маршрут приложения \`/toir/assets\` не должен конфликтовать с каталогом сборки \`/toir/assets/\`.

Для входа необходим собственный ТОИР backend по \`/toir/api/v1/\`. Сборки сайта не содержат паролей и конфигурации базы.


## Просмотр интерфейса до расширения API

В верхней панели авторизованного пользователя есть кнопка «Показать макет».
Она включает только в оперативной памяти браузера **визуальные демонстрационные записи** для всех реестров, нарядов, активов, планов, поставок, проектов и отчётов.

- Demo включается явно; по умолчанию всегда реальные данные из своей компании.
- Данные хранятся в \`src/demo/toirDemo.ts\`, не отправляются в API, не сохраняются в SQL.
- Над рабочей областью появляется заметная маркировка демо-режима.
- В демо можно просматривать карточки, формы, графики, переключать табы и фильтры. Кнопка сохранения заблокирована.
- Выключение демо возвращает фактическое содержимое базы.
- Просмотр сохраняется только в памяти вкладки, не в localStorage или cookies.

После визуального согласования демо-данные не становятся бизнес-данными автоматически: реальные операции реализуются и тестируются отдельными этапами.
